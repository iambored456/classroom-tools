# Validation preference

Keep verification focused and economical. Prefer the smallest relevant check and required build; avoid broad test suites, redundant browser checks, and repeated passing tests unless a new change, failure, or concrete risk warrants them. Summarize validation briefly.

# Settings

Apply preference changes as soon as the user selects them. For validated inputs, apply each valid change and keep the last valid value active while the input is incomplete or invalid. Settings panels should use a close control without Apply or Cancel buttons.
